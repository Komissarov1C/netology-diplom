#netology-diplom

Дипломный проект профессии «1C-программист: с нуля до middle» выполнил Комиссаров В.В. (@Komissarov1C)
Конфигурация: «Управление IT-фирмой»

#
Цель дипломного проекта:
  - Разработать и подготовить к эксплуатации новый функциональный блок в конфигурации «Управление IT-фирмой».

Вам нужно:
- реализовать новые подсистемы «Работа с заявками клиентов» и «Расчёт управленческой зарплаты» в соответствии с требованиями заказчика,
- подготовить отчёты по новой функциональности,
- оформить инструкцию по начальной настройке,
- подготовить автотест для проверки корректности работы подсистемы «Работа с заявками клиентов»,
- загрузить результат работы в новый репозиторий на GitHub.

Полная постановка задачи находится [здесь](https://github.com/netology-code/fonecmid-diplom/tree/main)

#
1. Назначение инструкции
Инструкция предназначена для сотрудников, ответственных за первоначальную настройку и эксплуатацию дополнительных подсистем информационной базы 1С:Предприятие.

После выполнения настроек пользователи смогут:
* регистрировать и планировать заявки на обслуживание клиентов с оповещением в telegram группе;
* фиксировать выполненные специалистами работы и затраченное время;
* оформлять документы реализации товаров и услуг и формировать акты;
* массово создавать документы реализации за выбранный период;
* рассчитывать управленческую заработную плату и фиксированные премии;
* вести графики работы и планировать отпуска;
* анализировать выработку специалистов, выставленные акты, расчёты с сотрудниками и использование запланированных отпусков.
  
Настройка выполняется в информационной базе, в которой уже ведётся учёт компании. Перенос существующих данных не требуется.

#
2. Подготовка к началу работы
Перед настройкой основной функциональности необходимо выполнить следующие действия:
* Создать резервную копию информационной базы;
* Убедиться, что в базу загружена версия конфигурации с разработанными подсистемами;
* Проверить отсутствие ошибок при запуске программы;
* Войти в программу под пользователем с административными правами;
* Убедиться, что необходимые справочники и документы доступны в интерфейсе;
* Подготовлены данные для Telegram-бота;
* Первоначальную настройку рекомендуется выполнять сначала в копии рабочей базы. После проверки корректности работы настройки можно перенести в рабочую информационную базу.

#
3. Настройка пользователей и прав доступа
Для разграничения доступа к данным необходимо назначить сотрудникам соответствующие профили групп доступа.

На данный момент были созданы Пользователи: Администратор, Бухгалтер, Кадровик-расчетчик, Менеджер по обслуживанию, Специалист. 
При необходимости можно завести новых Пользователей:
1. Откройте Администрирование - Настройки пользователей и прав - Пользователи.
2. Выберите пользователя (или создайте нового).
3. В карточке пользователя на закладке «Права» нажмите «Профили групп доступа» и отметьте нужный профиль (BKM_Менеджер по обслуживанию, BKM_Специалист, BKM_Бухгалтер, BKM_Кадровик-расчетчик).
4. Запишите и перезапишите пользователя.

В зависимости от обязанностей сотрудников предусмотрены следующие профили пользователей:
- Администратор - Полные права с настройкой программы, пользователей и системных параметров;
- BKM_КадровикРасчетчик - Ведение кадровых данных, условий оплаты, расчёт зарплаты и планирование отпусков;
- BKM_МенеджерПоОбслуживанию - Создание и планирование заявок клиентов;
- BKM_Специалист - Заполнение сведений о выполненных работах;
- ВКМ_Бухгалтер - Формирование документов реализации и актов оказанных услуг.

При необходимости можно завести новые Группы доступа через подсистему Администрирование - Настройки пользователей и прав - Профили групп доступа - Создать. 
В конфигурации предусмотрен отчёт - Права ролей профиля. Он помогает проверить, какие объекты метаданных доступны через роли, входящие в профиль. Используйте его для диагностики прав, если пользователь не видит команду или получает отказ в доступе.

#
4. Настройка подсистемы - Обслуживание клиентов
Подсистема предназначена для регистрации заявок клиентов, планирования работ специалистов и учёта фактически выполненных услуг.

  4.1. Проверка справочников
Перед созданием первой заявки необходимо проверить наличие следующих данных:
- контрагенты, представляющие клиентов компании;
- номенклатура услуг;
- договоры с клиентами;
- сотрудники, выполняющие работы и планирующие обслуживание.

Используйте существующие элементы справочников, если они уже заведены в информационной базе. Не создавайте дублирующие записи.

  4.2. Настройка Договоров на абонентское обслуживание
Для работы с заявками требуется договор соответствующего вида — абонентское обслуживание.
Откройте справочник договоров контрагентов и создайте новый договор либо проверьте существующий.

Заполните предусмотренные конфигурацией поля:
- клиент (контрагент);
- вид договора — абонентское обслуживание;
- дата начала действия;
- дата окончания действия;
- сумма ежемесячной абонентской платы;
- стоимость часа работы специалиста.

Проверьте корректность дат и денежных значений. Дата документа обслуживания должна соответствовать периоду действия договора. При регистрации и проведении документа программа должна проверять соблюдение этого условия.

  4.3. Настройка справочника Номенклатуры для актов
В справочнике «Номенклатура» создайте (или выберите существующие) позиции с видом "Услуги", которые будут отражаться в актах об оказании услуг. Рекомендуется завести две позиции если их нет:
- "Абонентская плата";
- "Работы специалиста".

Заполните соответствующие константы:
- BKM_НоменклатураАбонентскаяПлата (Номенклатура абонентская плата) — выбранная позиция абонентской платы;
- BKM_НоменклатураРаботыСпециалиста (Номенклатура работы специалиста) — выбранная позиция работ специалиста.

  4.4. Подготовка данных справочника Сотрудники
Перед созданием заявок необходимо проверить заполнение справочника Сотрудников (ВКМ_Сотрудники), используемого разработанной подсистемой.

  4.5. Настройка уведомлений через Telegram
В конфигурации реализовано оповещение специалистов через Telegram, перед использованием необходимо настроить интеграцию.
* Создайте/проверьте Telegram-бота и получите токен доступа;
* Подготовьте группу или чат, в который должны поступать уведомления;
* Добавьте бота в группу и предоставьте необходимые права;
* Получите идентификатор группы или чата;
* Заполните константы токена бота (Токен telegram bot) и идентификатора группы (Идентификатор группы telegram для оповещения);
* Проверьте доступность Telegram из среды, в которой работает информационная база;
* Настроено регламентное задание отправки уведомлений (Отправка уведомлений telegram) на каждый день с периодичностью 1 час;
* Токен Telegram является конфиденциальной информацией. Не размещайте его в открытом репозитории, документации общего доступа или сообщениях для посторонних лиц.

После настройки создайте тестовую заявку или измените данные существующей заявки в соответствии с условиями отправки уведомления. Убедитесь, что сообщение поступило в нужную группу.

5. Настройка подсистемы - Расчёт управленческой заработной платы
Подсистема используется для расчёта управленческой заработной платы, начисления премий и планирования отпусков.
Перед началом работы необходимо проверить кадровые данные и условия оплаты сотрудников.

  5.1. Настройка условий оплаты
Для каждого сотрудника необходимо заполнить предусмотренные разработанным механизмом условия оплаты.

В зависимости от категории сотрудника могут использоваться:
* должностной оклад;
* процент от стоимости выполненных работ;
* график работы.

Специалистам начисляется минимальный оклад и процент за выполненные работы клиентам. Административный персонал получает оклад.
Для специалистов, чья оплата зависит от выполненных работ, обязательно проверьте ставку или процент, используемый при расчёте.

  5.2. Настройка графиков работы
График работы устанавливается с помощью обработки - Заполнение графика, по периоду и выходным дням. Выходныие дни указываются в виде дней недели (1-7) с возможностью указать через запятую (6,7). График записывается в регистр сведений - Графики работ, рабочие дни обозначаются значением 8 (часов).

Порядок работы:
1. Заполнить период заполнения.
2. Заполните выходные дни.
3. Команда "Заполнить" график.

Не изменяйте стандартные графики без предварительной проверки их использования в существующем учёте.

  5.3. Настройка отпусков
В конфигурация использует специальный график для расчёта календарных дней отпуска.

При составлении графика отпусков:
- укажите сотрудника;
- заполните даты начала и окончания отпуска;
- проверьте дней отпуска, а также пересечений с остальными сотрудниками;

#
6. Настройка документов реализации товаров и услуг
Документ реализации используется для оформления оказанных клиентам услуг и формирования акта.

  6.1. Проверка автоматического заполнения документа
Порядок работы:
1. Откройте документ реализации товаров и услуг.
2. Выберите клиента и договор на абонентское обслуживание.
3. Укажите дату документа и остальные обязательные реквизиты.
4. Выполните предусмотренную команду автоматического заполнения.
5. Проверьте наличие строки абонентской платы, если она предусмотрена договором.
6. Проверьте наличие строки выполненных работ за соответствующий период.
7. Сверьте суммы с договором и документами обслуживания.
8. Проверьте документ и сформируйте печатную форму акта.

Если строки не заполняются автоматически, проверьте вид договора, период документа, заполнение констант и наличие проведённых документов обслуживания.

  6.2 Настройка массового создания документов реализации
Обработка массового создания документов предназначена для подготовки документов реализации по договорам абонентского обслуживания за выбранный период.

Перед первым использованием убедитесь, что:
- заполнены необходимые договоры;
- указаны корректные сроки действия договоров;
- настроена номенклатура услуг;
- заполнены и проведены документы обслуживания, если они требуются для расчёта стоимости выполненных работ;
- пользователь имеет права на запуск обработки и создание документов реализации.

Порядок работы:
1. Откройте обработку массового создания документов реализации.
2. Выберите расчётный период.
3. Сформируйте список договоров, по которым необходимо подготовить документы.
4. Проверьте список и сведения о ранее созданных документах.
5. Запустите создание документов.
6. Дождитесь завершения операции.

Проверьте сформированные документы и при необходимости перепроведите их в установленном порядке.
За один и тот же период не должны создаваться дублирующие документы по одному договору.

7. Отчёты  подсистем
В конфигурации добавлены четыре отчёта. Они используются для контроля обслуживания клиентов и анализа расчётов с сотрудниками.
Для получения корректных данных сначала внесите и проведите документы, на основании которых строится отчёт. Если отчёт пустой, проверьте период, фильтры, наличие исходных документов и права пользователя.

  7.1.  Отчет "Выработка специалистов"
Назначение: показать за выбранный период, сколько часов отработал специалист и какая сумма начислена ему в виде процента от оплаты выполненных работ клиентами.
Кому нужен: специалистам и кадровику-расчётчику согласно правам доступа.

Порядок формирования:
1. Откройте отчёт в подсистемах Обслуживание клиентов и Расчет управленческой зарплаты.
2. Укажите период, за который требуется получить данные.
3. При необходимости выберите конкретного Сотрудника.
4. Нажмите "Сформировать".
5. Проверьте количество часов и сумму, рассчитанную как процент от выполненных работ.

  7.2. Отчет "Анализ выставленных актов"
Назначение: показать клиентов, договоры и суммы, которые необходимо выставить клиентам на основании данных документов «Обслуживание клиентов».
Кому нужен: бухгалтеру; для открытия отчёта у пользователя должен быть доступ к роли использования отчёта.

Порядок формирования:
1. Откройте отчёт в подсистеме Обслуживание клиентов.
2. Укажите период анализа.
3. При необходимости выберите конкретного Контрагента.
4. Нажмите "Сформировать".
5. Сопоставьте клиентов и договоры с суммами, рассчитанными по данным обслуживания.
6. Используйте отчёт для проверки полноты подготовки реализации за период.

  7.3. Отчет "Расчёты с сотрудниками"
Назначение: показать начисленные и выплаченные суммы по каждому сотруднику за выбранный период, а также задолженность на начало и конец периода.
Кому нужен: кадровику-расчётчику и другим уполномоченным сотрудникам согласно правам доступа.

Порядок формирования:
1. Откройте отчёт в подсистеме Расчёт управленческой заработной платы.
2. Укажите период анализа.
3. При необходимости выберите конкретного Сотрудника.
4. Нажмите "Сформировать".
5. Проверьте начисления, выплаты и задолженность на начало и конец периода.

  7.4. Отчет "Расход запланированных отпусков"
Назначение: показать по сотрудникам плановую продолжительность отпуска и количество дней, фактически использованных в выбранном календарном году.
Кому нужен: кадровику-расчётчику и другим сотрудникам согласно правам доступа.

Порядок формирования:
1. Откройте отчёт "Расход запланированных отпусков" в подсистеме Расчёт управленческой заработной платы.
2. Укажите год, за который требуется получить сведения.
3. Нажмите "Сформировать".
4. Сравните плановую продолжительность отпуска с количеством дней фактического отпуска, отражённых в данных информационной базы.

  7.5. Права доступа к отчётам
В используемом примере реализации предусмотрены отдельные роли использования отчётов. При настройке вашей информационной базы проверьте фактическое наличие этих ролей и их включение в профили групп доступа.
Выработка специалистов	- BKM_Специалист, BKM_Кадровик-расчетчик;
Анализ выставленных актов	-	BKM_Бухгалтер;
Расчёты с сотрудниками	- BKM_Кадровик-расчетчик;
Расход запланированных отпусков -	BKM_Кадровик-расчетчик;
